# テスト駆動開発（TDD）ナレッジ

## 鉄則

```
失敗するテストなしに本番コードを書かない
```

テストより先にコードを書いたら、削除してやり直す。例外なし。

## Red-Green-Refactor サイクル

| フェーズ | やること | 必須確認 |
|---------|---------|---------|
| **RED** | 失敗するテストを1つ書く | - |
| **確認** | テスト実行、期待通りに失敗 | 必須 |
| **GREEN** | テストを通す最小限のコード | - |
| **確認** | テスト実行、通ることを確認 | 必須 |
| **REFACTOR** | テストが通る状態を維持しながら改善 | - |

## 良いテストの条件

- **1テスト = 1つの振る舞い**（名前に「and」が入るなら分割）
- **テスト名で何をテストしているか明確**
- **モックは避け、実際のコードをテスト**
