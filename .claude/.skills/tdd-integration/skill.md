# TDD統合テスト
専用のサブエージェントを用いて、Red-Green-Refactorサイクルによる厳格なテスト駆動開発を強制します。

## 必須ワークフロー
すべての実装は、必ずこの厳格な3段階のサイクルに従わなければなりません。フェーズをスキップしないでください。

### フェーズ 1: RED - 失敗するテストを書く

🔴 RED PHASE: tdd-test-writer に委譲中...

以下の内容で tdd-test-writer サブエージェントを呼び出します：
- ユーザーリクエストからの機能要件
- テストすべき期待される振る舞い

サブエージェントは以下を返します：
- テストファイルのパス
- テストが失敗したことを確認するエラー出力
- テストが何を検証するかについての要約

**テストの失敗が確認されるまで、Greenフェーズに進んではいけません。**

## フェーズ 2: GREEN - パスさせる
🟢 GREEN PHASE: tdd-implementer に委譲中...

以下の内容で tdd-implementer サブエージェントを呼び出します：
- REDフェーズからのテストファイルのパス
- 機能要件のコンテキスト

サブエージェントは以下を返します：
- 修正されたファイル
- テストがパスしたことを確認する成功の出力
- 実装の要約

**テストがパスするまで、Refactorフェーズに進んではいけません。**

## フェーズ 3: REFACTOR - 改善する
🔵 REFACTOR PHASE: tdd-refactorer に委譲中...

以下の内容で tdd-refactorer サブエージェントを呼び出します：
- テストファイルのパス
- GREENフェーズからの実装ファイル

サブエージェントは以下のいずれかを返します：
- 実施された変更 + テスト成功の出力、または
- 「リファクタリング不要」という文言とその理由

**リファクタリングフェーズからの返答をもって、サイクルは完了します。**

## 複数機能の取り扱い

次の機能を開始する前に、各機能に対して全サイクルを完了させてください：

機能 1: 🔴 → 🟢 → 🔵 ✓ 
機能 2: 🔴 → 🟢 → 🔵 ✓ 
機能 3: 🔴 → 🟢 → 🔵 ✓

## フェーズ違反 (Phase Violations)
以下の行為は禁止します：
- テストを書く前に実装を書く
- Redの失敗を確認せずにGreenへ進む
- リファクタリングの評価をスキップする
- 現在のサイクルを完了する前に新しい機能に着手する
